### 調査方法についての補足(技術的な注記)

この年間行事予定表PDFは、Excelで作成された12ヶ月分の表を1ページの画像的なレイアウトで書き出したもので、通常のテキスト抽出(WebFetch、`pdftotext`)では列(月)と行(日付)の対応関係が正しく復元できなかった。
そのため、PDFを**画像として高解像度でレンダリングし、月の列と日付の行が視覚的に正しく対応していることを確認しながら**目視で転記する方法に切り替えた。

その過程で、**PDF内に印字されている曜日(火・水・木...)の表記そのものに誤りがある**ことが判明した
(例: PDF上は9月1日に「木」の表記があるが、実際の2026年9月1日は火曜日)。日付の数字(1, 2, 3…)自体は月の見出しと矛盾なく、
スポーツの日(10月第2月曜)・成人の日(1月第2月曜)・大学入学共通テスト(1月の土日)・振替休日が春分の日の翌日に来る、といった
**独立に検証可能な複数のルールと完全に整合する**ため、以下の一覧では「日付(何月何日)」は資料の記載を信頼し、
**曜日は実際のカレンダーに基づき本調査で計算し直したもの**を表示している。

## 9. 不明点・注意事項

1. **「体育祭」に相当する行事が明確に1つではない**: 資料上は「空高杯」という校内スポーツ大会が **9月・11月の少なくとも2回**、それぞれ複数日(①〜⑥等)にわたって開催されている。一般的な「体育祭」(1日開催の全校行事)とは性質が異なる可能性があり、**どちらか(または両方)を「体育祭」としてカウントダウン対象にするかは学校への確認、または生徒への聞き取りを推奨**する。
2. **「文化祭」に相当する行事が見当たらない**: ユーザーの依頼文には「学校祭」という言葉があったが、令和8年度の資料からは「文化祭」という単独の全校公開行事は確認できなかった。「探究発表会」(9月・10月に複数回登場)がその役割を兼ねている可能性がある。**要確認**。
3. **修学旅行の実施内容**: 「研修験学旅行」という名称で①〜⑤の番号付きで11月末〜12月上旬に登場するが、学年・コース別の詳細な行程(対象学年、宿泊数、目的地)はこの予定表からは読み取れない。
4. **冬季休業の正確な開始日・終了日**: 開始日(12/23)は番号①の初出から高い確度で特定できたが、終了日(1/14 → 1/15授業再開)は「番号が㉓で止まり、1/15から通常表記に戻る」という**間接的な推測**であり、学校からの直接的な文言(「1月15日始業」等)ではない。**本番のデータとして使う前に、学校からの正式な始業案内(1月頃に配布されることが多い)で再確認することを強く推奨する**。
5. **春分の日(2027年3月21日)**: 国立天文台が「暦要項」として毎年2月頃に翌年の春分・秋分日を官報で正式公表するため、本調査時点(令和8年度予定表作成時)ではまだ天文学的に確定していない可能性がある。予定表に記載があるため大きくずれることはないが、**2027年2月頃に最新の官報を再確認するのが望ましい**。
6. **PDF内の曜日表記の誤り**: [1章](#1-調査した公式資料)に記載の通り、PDFに印字された曜日文字そのものに誤りがあることを確認した。日付の数字は信頼できるが、学校側の資料に何らかの入力・書式ミスがある可能性が高く、**将来的に学校から新しい改訂版が出た場合は再取得・再照合が必要**。
7. **行事の変更可能性**: 学校行事ページ自体に「実施月が変更される場合があります」と明記されており、この予定表も「改訂版」であることから、**年度途中でさらに変更される可能性は十分にある**。これが今回の要件([7. イベントデータ設計](#7-イベントデータ設計)で管理画面から編集可能にする理由)に直結している。

## 10. 今後の実装案

### データ設計(ユーザー指定の方向性を踏襲)

```ts
interface SchoolEvent {
  id: string;
  name: string;          // 画面表示名(学校名・原資料の固有名詞は含めない。例: "空高杯"→"体育祭" 等、一般化して表示するか要検討)
  startDate: string;     // ISO日付
  endDate: string;       // 単日イベントは startDate と同じ
  type: "exam" | "festival" | "sports" | "trip" | "holiday" | "ceremony" | "other";
  countdownEnabled: boolean;
  seasonalTheme?: "autumn" | "winter" | "christmas" | "newyear" | "spring" | null;
  character?: string;    // 季節コンテンツのキャラクター種別(9章のアイデア用、任意)
  message?: string;      // カウントダウン中の表示メッセージ
  afterMessage?: string; // イベント終了後の表示(例: "お疲れさまでした")
  priority: number;      // 表示優先度
  confidence: "confirmed" | "estimated" | "unconfirmed"; // 5章の確実性A/B/Cに対応
  enabled: boolean;
  sourceNote?: string;   // 「学校公式資料(2026/6/29改訂版)より」等、根拠を残す
}
```

学年度(2026年度)に紐づく形ではなく、**年度をまたいで再利用できる汎用テーブル**として設計し、管理画面から
「名前」「開始日」「終了日」「カウントダウン対象か」「表示優先度」「季節テーマ」「キャラクター」「表示メッセージ」「終了後の表示」「有効/無効」を
編集できるようにする(ユーザー要件どおり、コードにハードコーディングしすぎない)。

## UX視点の提案: どの行事をカウントダウン対象にすると生徒が毎日見たくなるか

### 毎日変化するもの(最優先候補)

- **冬季休業までのカウントダウン(12/23開始)**: 9月〜12月という長い期間、日々「あと◯日」が動き続ける。ユーザーの例(サンタが少しずつ歩く)に最も適した対象。学期末に向けて盛り上がりが自然に高まる。
- **後期開始式(10/1)からの経過**、**冬休み明け(1/15)までのカウントダウン**: 長期休業の始まりと終わりの両方をカウントダウン対象にすることで、9月から3月まで切れ目なく「今は年間のどのあたりか」を感じられる。

### 数週間前から楽しめるもの

- **ふきおろしマラソン(10/18)**: 校内行事で全生徒が当事者になりやすく、秋らしさも出しやすい。
- **空高杯(9月・11月)**: 体育祭相当の行事だとすれば、複数回あることを逆手に取り、「今シーズン◯回目」のような区切りでカウントダウンできる。
- **大学入学共通テスト(1/16-17)**: 3年次にとっては最大の関心事。学年を絞った表示との相性が良い。

### 前日になると盛り上がるもの

- **修了式・卒業式**: 学年末の節目。前日に「明日は卒業式です」のような特別表示に切り替える演出が合う。
- **冬季休業前日(12/22)**: 「明日から冬休み!」の一言演出との相性が良い。

### 当日に特別演出できるもの

- **冬季休業開始日(12/23)**、**元旦(1/1)**、**後期開始式(10/1)**、**卒業式(3/1)**: いずれも「今日で切り替わる」ことが明確な日。ユーザーが提示した「サンタが目的地に到着」のような一度きりの演出に向く。

### 終了後にも余韻を残せるもの

- **ふきおろしマラソン・空高杯**: 「お疲れさまでした」的な短い余韻表示との相性が良い(行事直後は生徒の関心が残っている)。
- **冬季休業明け(1/15)**: 「今年もよろしく」のような形で春に向けた雰囲気に切り替えるきっかけにできる。
- **卒業式(3/1)後**: 在校生向けに「新しい学年まであと◯日」につなげる自然な導線になる。

### 総合的な推薦

O-schoolのトップページでは、**「季節を通した1本の背景ストーリー」**(9月:まだ暖かい→ 秋のマラソン → 冬休みへ向けたカウントダウン →
冬休み中の季節演出(サンタ等)→ 冬休み明け → 共通テスト → 春休み・卒業)という**1本の連続した体験**として設計するのが、
個別イベントをバラバラに並べるより「毎日ちょっと違う」を感じやすいと考えられる。この設計思想の実装方法は、次の作業ステップで別途検討する。
